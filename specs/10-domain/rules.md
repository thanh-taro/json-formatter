# Rules & limits

Sizes are measured in bytes of UTF-8 text; 1 MB = 1,000,000 bytes.

| ID | Rule |
|---|---|
| **RULE-01** | Indent styles: 2 spaces (default), 4 spaces, tab, or a custom number of spaces from 1 to 8. |
| **RULE-02** | Size tiers, re-evaluated whenever the document changes (paste, typing, load): *normal* ≤ 10 MB — everything enabled; *large* > 10 MB to 100 MB — fully supported, visual extras (e.g. syntax colouring) may be reduced and the user is told once on entering the tier; *very large* > 100 MB — best effort: loading a file, or pasting text that would make the document exceed 100 MB, requires confirmation first; if the device cannot hold it, the operation stops with an explanation and the previous document is kept. A beautify or re-indent whose result would exceed 100 MB requires the same confirmation first. |
| **RULE-03** | Validity follows the JSON standard (RFC 8259) strictly: any value at top level; whitespace is space, tab, line feed, carriage return. A leading byte-order mark is tolerated, kept as the first character of the document, and reported as a warning. Anything else non-standard (comments, trailing commas, single quotes…) is an error. A document of zero characters is *empty* — neither valid nor invalid, no issue. |
| **RULE-04** | Errors — only the first syntax error is reported. Each code has its own hint. Position (line, column) is where the error is reported: `trailing-comma` — the comma; `comment` — the first `/`; `single-quotes` — the opening `'`; `unquoted-key` — first character of the key; `missing-comma` — first character of the token after the missing comma; `missing-colon` — first character of the token after the key; `unclosed-string` — the opening quote; `unclosed-container` — end of document (the hint names the bracket and the line it opened on); `unexpected-closing` — the bracket; `invalid-literal` — first character of the word; `invalid-number` — first character of the number; `invalid-escape` — the backslash; `control-character` — the character; `extra-content` — first character after the top-level value; `empty-document` — line 1, column 1 (document is non-empty but contains only whitespace); `too-deep` — the opening bracket that exceeds RULE-14; `unexpected-character` (fallback) — the character. |
| **RULE-05** | Warnings (document stays valid), each located at the first character of the item: `duplicate-key` — every repeated member name after its first occurrence in the same object (all occurrences kept); `unsafe-number` — an integer literal (no fraction, no exponent) whose absolute value exceeds 2^53−1, a number with more than 17 significant digits, a number too large to represent as a double-precision value (overflows to infinity), or a non-zero number that would round to zero. (`0.1`, `1.50`, `1e3` are not flagged.) `byte-order-mark` — line 1, column 1. Warnings are capped at 1,000 with a count of the rest. |
| **RULE-06** | Path notation: root is `$`; object member `.name` when the name is an ASCII letter, `_` or `$` followed by ASCII letters, digits, `_` or `$`; otherwise `["name"]` with JSON string escaping; array element `[n]` (0-based). Example: `$.items[0]["content-type"]`. |
| **RULE-07** | Beautify layout: each object member and array element on its own line, indented one level per nesting depth with the chosen indent style; `"key": value` with one space after the colon; empty object `{}` and empty array `[]` on one line. Line breaks use the document's line ending (line feed if it had none). The result ends with a line break only if the input ended with one. A byte-order mark stays the first character. |
| **RULE-08** | Minify layout: no whitespace outside strings and no line breaks. A byte-order mark stays the first character. |
| **RULE-09** | Re-indent. *Leading indentation* is the run of spaces and tabs at the start of a line. *Source unit*: if more indented lines start with a tab than with a space, the unit is one tab; otherwise it is N spaces, where N is the most frequent positive increase in leading-space count between consecutive non-blank lines (ties → the smaller N); if no such increase exists, N is the smallest positive leading-space count. When the unit is a tab, N is still computed from space-indented lines; if there are none, leading spaces are kept unchanged. *Conversion* of each line: each tab = 1 unit; spaces = ⌊count ÷ N⌋ units, the remaining spaces are kept after the converted units; the line becomes that many units of the target style followed by the rest of the line unchanged. Blank lines and line breaks are unchanged. If no line is indented, nothing changes. |
| **RULE-10** | Download file name: the original file name when the document came from a file; otherwise `formatted.json` if the most recent tool operation was beautify, `minified.json` if it was minify, else `document.json`. Content is saved exactly as shown, encoded as UTF-8. |
| **RULE-11** | Copy value of a node: its source text exactly as written in the document (strings include their quotes; numbers keep their spelling; containers include everything from their opening to their closing bracket). |
| **RULE-12** | Tree expansion: when the tree is first shown, the root and its direct children are expanded. Containers with more than 100 children show them in groups by position (`[0 … 99]`, `[100 … 199]`, …; objects use member positions the same way). With more than 10,000 children, groups are nested (groups of 10,000 containing groups of 100, and so on by factors of 100). Group rows have no copy actions. |
| **RULE-13** | Input encoding: files are read as UTF-8, with or without byte-order mark (which is kept, RULE-03). A file that is not valid UTF-8 is not loaded; the user is told why and the previous document is kept. |
| **RULE-14** | Nesting depth: documents nested up to 10,000 levels are supported; deeper nesting is an error (`too-deep`). |
| **RULE-15** | Undo history: in the normal tier at least the last 100 changes can be undone; in the large and very large tiers at least the last 3 tool operations (load, clear, beautify, minify, re-indent) can be undone, older history is dropped and the user is told once. |
| **RULE-16** | Host settings contract: the host passes the initial theme (`light` or `dark`) in the tool's address when opening it; later changes arrive as settings messages. The tool signals the host once it is ready; that ready signal is the only message the tool ever sends. The list of allowed host origins is fixed when the tool is deployed; it decides both who may embed the tool and whose messages are accepted. If the list is empty, the tool cannot be embedded and runs standalone only. |
| **RULE-17** | Line endings: when a document is loaded or pasted, mixed line breaks (LF and CRLF together) are normalised to the dominant one (ties → LF). Line breaks are insignificant whitespace, so this keeps INV-01. |
| **RULE-18** | Find: matching is literal text (no patterns), case-insensitive unless match case is on; matches never overlap; searching wraps from the end to the start. |
