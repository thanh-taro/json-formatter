## Context
ADR-0009 fixes the tool's response headers (CSP, frame-ancestors from the allow-list). The F-008
security review (build/F-008/security-1.md, M4) noted that no HSTS header is sent. The tool's
domain is under `.app`, which browsers already force to HTTPS (portal ADR-0001), but an explicit
header also covers clients without the preload list and documents the intent.

## Decision
The generated headers add `Strict-Transport-Security: max-age=31536000; includeSubDomains`
for every path. This adds to ADR-0009; nothing in it changes.

## Alternatives considered
- Rely on the `.app` preload list only — works in current browsers, but leaves the intent implicit.
- Add `preload` — a site-wide commitment owned by the portal's domain, not by one tool.

## Consequences
- Generated by MOD-Build's header script and covered by its header unit test.
- Removing HTTPS later would need the max-age to expire first.
