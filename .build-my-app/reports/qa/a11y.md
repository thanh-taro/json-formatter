# M-1 JSON Formatter accessibility audit (NFR-06, WCAG 2.2 AA)

Build: `pnpm build`, served by `E2E_PORT_BASE=4373 node tests/e2e/server.mjs`. Engines: Chromium and WebKit (Playwright 1.63; Firefox not run). Product code unchanged. Scripts are in the session scratchpad (not part of the repo).
Spec basis: `spec_query.py context SCR-Formatter --full` (SCR-Formatter and the CMP-* Accessibility sections).

## 1. Automated results

### axe-core 4.13 (wcag2a, 2aa, 21a, 21aa, 22aa, best-practice), 28 states x 2 browsers
States: empty, loaded, tree, find open (query typed), invalid (+ tree-invalid), warnings, privacy popover, notice-large (34 MB), notice-error (bad UTF-8, alert), confirm dialog (132 MB), busy (progress), narrow 390 coarse (empty, invalid). Themes: dark and light.
- Zero violations at WCAG A/AA in all states, both themes, both engines.
- Two best-practice hits in nearly every state: `page-has-heading-one` (moderate) and `region` (the `.tk-toolbar` is outside a landmark) (moderate). The tool is embedded in the portal, so verify against the host page. See m1.
- axe "incomplete" for `color-contrast` (privacy popover, dialog, find, light theme). Resolved by the manual computation below.

### Contrast (computed in real renders, both themes, 6 states)
- All text is at least 4.5:1 (large text at least 3:1). Lowest: light error text 5.03:1, dark editor `{` 5.24:1.
- Non-text: accent focus ring 6.3:1 (dark and light); `line-strong` borders 3.5:1 (dark and light); danger and success at least 5.6:1. Pass (1.4.11).
- Hairline `line` (1.3:1) is only decorative separators.

### Keyboard, focus, structure (Chromium; WebKit partial, see M5)
- Reading order is toolbar, main, issues, status bar. It matches the spec.
- Toolbar: roving tabindex works. Exactly one Tab stop; Left, Right, Home and End work and wrap. Arrow keys do not trap.
- Tree: `role=tree` with treeitems (level, expanded, selected). One tab stop; Up, Down, Left, Right, Home and End work. "Show in text" returns focus to the editor.
- Issue tabs: roving tabindex with arrow keys. Escape closes find and returns focus to the editor (also after Ctrl+F). Privacy popover: Escape closes it and focus returns to its trigger.
- Editor: no trap. Tab leaves to the next control and Shift+Tab goes back. CodeMirror binds no Tab key, so the documented "escape from Tab insertion" is moot. A literal tab can only be pasted or entered via re-indent (info, not a defect).
- Confirm dialog: native `<dialog>`; Cancel has initial focus; Tab cycles inside; Escape cancels. Focus returns to the editor when the editor was the trigger.
- Focus ring: 2 px solid accent on every control. The editor shows only its caret (`outline:none`).
- Live regions (recorded with MutationObserver):
  - Validity: `role=status`; one announcement per changed error; "Empty" and "Valid JSON . 1 warning" announced once.
  - Copy toast: "Copied", once. Encoding error bar: `role=alert`, once.
  - Find count: "1 of 2", then "2 of 2" on Enter, once each. "No matches" is announced.
  - Repeating the same error with Beautify or Minify announces nothing (by design; see M2).
- Names: toolbar "Document actions", view group "View" (Text, Tree pressed), editor "JSON document", tree "Document tree", issues "Issues", find field "Find in document", dialog named "Large content" with a description. All match their COPY IDs.
- Reflow at 200% (640 CSS px): no horizontal page overflow. Toolbar scrolls inside itself (toolbars are a 1.4.10 exception).
- Text spacing (line-height 1.5, letter 0.12em, word 0.16em): no clipping or overflow in the status bar, issues, notices or toolbar.
- Reduced motion: only the toast fade/slide is animated, and it is gated on `no-preference`. No animation found with `reduce`.

## 2. Findings

### Blocker
None.

### Major
**M-A1. Reflow fails at 320 CSS px (WCAG 1.4.10).**
- Element: `html`/`.tk-formatter`, `min-width: var(--tk-size-min-width)` = 360 px (`src/app/styles/base.css:17`, `tokens.gen.css:47`).
- Evidence: at 320x256 `scrollWidth` is 360, so the page scrolls horizontally. The tool, notice slot and editor are 360 wide.
- Fix: drop the page-level min-width, or lower it to 320 and let the toolbar scroll or overflow. Check the status bar, issues and search panel at 320. (NFR-07's 360 conflicts with NFR-06 at 320; reconcile the NFR.)

**M-A2. Selected state invisible in forced colors (1.4.1, 1.4.11; Windows High Contrast).**
- Elements: the Text/Tree `aria-pressed` buttons, the Problems/Warnings tabs (selected tab marked only by an inset `box-shadow`), the match-case toggle and the selected tree row.
- Evidence: Chromium `forcedColors: active` screenshot shows pressed and unpressed Text/Tree identical (same border, same canvas background). The selected tab has no underline.
- Cause: no `@media (forced-colors: active)` rule exists anywhere in `src/`.
- Fix: add forced-colors rules, e.g. `[aria-pressed=true], [aria-selected=true]{background:Highlight;color:HighlightText}` (or `border-width:2px`), tab `border-bottom:3px solid`, selected tree row `outline:2px solid Highlight`. Use `forced-color-adjust:none` only for the error and warning markers.

**M-A3. Focus lost to `<body>` after busy operations and notice dismissal (2.4.3, NFR-06 full keyboard).**
- Elements: toolbar Open, Minify and Beautify, the file-confirm Cancel/Continue, the notice dismiss button.
- Evidence (Chromium and WebKit):
  - Focus on Minify, Enter. The toolbar becomes disabled, focus goes to body, and stays on body after completion.
  - Open file, then Cancel in the confirm dialog: focus is body.
  - Escape on a notice bar button removes the bar and focus goes to body.
  - Contrast: when the trigger was the editor, focus returned correctly.
- Fix: record the invoker before disabling. When busy ends, or on dismiss or cancel, restore focus to the invoker (or the editor if it is gone). While busy, move focus to Cancel or keep it on a `aria-disabled` control.

**M-A4. WebKit: privacy button, find buttons, issue and tree header buttons skipped by Tab (needs a real Safari check).**
- Evidence: in Playwright WebKit, Tab moves editor to body and never reaches "Local only", the find Match case/Previous/Next/Close, "Hide issues", issue rows or the status "Invalid JSON" button. The toolbar works because it sets `tabindex=0` explicitly.
- Cause: Safari's default "Press Tab to highlight each item" is off, so native buttons are excluded from Tab.
- Fix: set `tabindex="0"` on non-toolbar buttons (or provide a documented Option+Tab note). Confirm in real Safari (M5).

### Minor
- **m1.** No `h1` and the toolbar is outside any landmark (axe `page-has-heading-one`, `region`). Add a visually-hidden `<h1>` (e.g. the tool name) and wrap the toolbar in `<header>`. The host portal may provide these when embedded; confirm.
- **m2.** Coarse pointer (390 px, touch): toolbar buttons are 28 px high (Open, Clear, Find, Beautify, Minify, Re-indent, Text, Tree, Copy, Download), the empty-state Open button is 28 px, notice Dismiss and Open are 24 px, and "Hide issues" is 24 px. All pass 2.5.8 (24 px) but miss the spec's `size.touchTarget` 44 px (CMP-Toolbar, CMP-Notice). The `(pointer: coarse)` rule covers the status bar, issues, search and tree only. Fix: a coarse `min-block-size: 44px` on `.tk-toolbar .tk-button`, `.tk-icon-button`, `.tk-editor__empty-open`.
- **m3.** The narrow toolbar does not collapse to a "More actions" overflow menu (`COPY-action.more` exists but is unused, CMP-Toolbar "narrow"). It scrolls horizontally instead, and Download is clipped. This deviates from the spec.
- **m4.** Editor focus has only the caret and no ring (`theme.ts` `&.cm-focused{outline:none}`). Passes 2.4.7 via the caret, but is weak with the caret blink off or in forced colors. Add an inset 2 px accent ring on `.cm-editor.cm-focused`.
- **m5.** "Go to error" (issue row, status "Invalid JSON", tree "Go to error") moves the editor cursor but keeps focus on the clicked control. A keyboard or screen-reader user gets no feedback. Consider moving focus to the editor (F-005.AC6 says "cursor moves"; F-002.R4 says error "focused").
- **m6.** Each issue row's accessible name appends the raw code ("... Line 2, column 8 trailing-comma"). Hide the code from AT or place it last in `aria-hidden`. The list inside `tabpanel` is fine.
- **m7.** While tree view is active the empty `region "JSON document"` remains in the a11y tree (and the find panel stays inside it). Hide the inactive editor region with `hidden` or `inert`.
- **m8.** WebKit (desktop, fine pointer): the indent `<select>` is 23 px high, below 24 px (2.5.8). Add `min-block-size: 24px`.
- **m9.** Typing continuously in invalid JSON announces each changed error message: 3 announcements in ~1 s. This is within "once per new error" but chatty. Consider a 500 ms debounce of the announcement.
- **m10.** All font sizes are px tokens. Browser zoom works; a user-set default font size is ignored. Optional: rem for non-editor UI.
- **m11.** Forced colors: the validity dot disappears (text still says "Invalid JSON"). The editor error line background is lost; only the squiggle and the bold line number remain. Acceptable, but add a text or border marker.
- **m12.** The progress notice (`role=status`) announces on every percent change. Verify verbosity in M2; consider `aria-live=off` on the label and announce only start and end.

## 3. Manual pass required (real screen reader and real devices)

Run each with VoiceOver (Safari, macOS; also iOS), NVDA (Firefox and Chrome, Windows) and, if possible, JAWS.

- **M1 Landmarks and names.** Open the tool. VO: Ctrl+Opt+U (rotor), then Landmarks, Headings and Form Controls. NVDA: D, H, B and the Elements List. Expect: toolbar "Document actions", region "JSON document", region "Issues", status bar (contentinfo). Each button reads its COPY label. Heading absence (m1) is expected to show.
- **M2 Validity announcements.** Focus the editor, paste `{"a":1,}`. Expect one announcement: "Invalid JSON. Line 1, column 7. Remove the comma...". Type one more char: no announcement unless the error changes. Fix it, expect "Valid JSON". Clear, expect "Empty". Paste `{"a":1,"a":2}`, expect "Valid JSON . 1 warning". Press Beautify on invalid JSON: check that you get some feedback (m5; same error announces nothing).
- **M3 Issue list.** Tab or arrow to the Issues region. Each row should read "Error, hint, Line N column M". Activate it and confirm the cursor line is spoken in the editor (m5).
- **M4 Toasts and notices.** Load valid JSON, Copy: hear "Copied" once. Open a non-UTF-8 file: hear the alert once, then Escape or Dismiss and note where focus lands (M-A3). Load a 30 MB file: hear the large notice and progress (check chatter, m12).
- **M5 Safari keyboard.** Safari with defaults (Tab-highlight off): press Tab through the whole page. Confirm whether "Local only", find buttons, issue rows and "Hide issues" are reachable (M-A4). Repeat with Option+Tab.
- **M6 Tree.** Switch to Tree (VO: VO+Space on "Tree"). Enter the tree: VO should announce "Document tree, tree", then "$ object 2 keys, expanded, level 1, 1 of 1". Use arrows; check expand/collapse announcements and position ("2 of 4"). Select a row, Tab to "Copy path" and "Show in text".
- **M7 Find.** Ctrl/Cmd+F in the editor, type a query: expect "1 of N", then "2 of N" on Enter, "No matches" for a miss. Escape returns focus to the editor.
- **M8 Confirm dialog.** Paste or open a 120+ MB file. Expect "Large content, dialog" plus the description (size). Tab stays inside. Escape cancels and focus returns (see M-A3 for file-open).
- **M9 Editor reading.** In VO and NVDA, arrow through a few lines. Check the editor is announced as a multi-line edit field and that line and column are readable (CodeMirror contenteditable; known screen-reader variance).
- **M10 Touch and zoom.** iOS Safari: VoiceOver swipe order through toolbar, editor, issues, status. Pinch-zoom and Dynamic Type; Android TalkBack with the narrow layout; confirm targets are comfortable (m2).
- **M11 Forced colors and 400% zoom.** Windows High Contrast (Edge): verify Text/Tree pressed, tab selected, tree selected row and error marker are distinguishable (M-A2). Browser zoom to 400% (320 CSS px): confirm no horizontal page scroll (M-A1).
- **M12 Reduced motion.** Set OS "Reduce motion" and confirm the toast does not slide. Confirm the progress bar is not animated beyond width.

## 4. Not covered
Firefox, real devices and screen readers, the portal host embedding (iframe focus handoff and host landmarks), the very-large tree-unavailable state, and drag-and-drop with assistive technology (the Open action is the non-drag alternative and works by keyboard).
