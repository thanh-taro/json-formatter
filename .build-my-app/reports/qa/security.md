# QA — security and privacy audit, JSON Formatter M-1

Date: 2026-10-14. Scope: `src/**`, `scripts/**`, `public/`, `dist/` (fresh `vite build` into a
scratch directory; deployable files are byte-identical to the committed `dist/`, apart from the
relative source paths inside the `.map` files), `pnpm-lock.yaml`, `pnpm-workspace.yaml`,
`.github/workflows/ci.yml`, `eslint.config.js`, `vite.config.ts`. Checked against: NFR-01
(+D-021, D-028), INV-02, NFR-09, F-008, F-009, F-011, ADR-0001/0003/0008/0009/0012. No product
code was changed.

**Result: 0 blocker, 2 major, 6 minor, 6 info.** The app itself (runtime code and headers) has
no exploitable defect. The two majors are (1) deploy-time controls that the repo cannot verify
yet and (2) a browser-translation path that can send document text off the device.

## Verified OK

- **No network after load (NFR-01, INV-02).** The shipped JS (`assets/index--LrwBnkG.js`, the
  worker chunk `assets/index-UbcRPOw5.js`, `assets/tree-BfNp9vAt.js`) has no `fetch`,
  `XMLHttpRequest`, `sendBeacon`, `WebSocket`, `EventSource`, `importScripts`, `eval` or
  `new Function`. `fetch` appears only in `dist/sw.js` (3×: network-first page, asset cache
  miss, `force-cache` seeding: the D-021 exception). The only absolute URL in the bundle is
  `https://tarokit.app` (the compiled-in allow-list), plus XML namespace strings. Fonts and
  icons are self-hosted (`url(/assets/*.woff2)` only). `modulePreload.polyfill: false`
  (`vite.config.ts:29`). ESLint bans network, storage and navigation APIs, and bans
  `postMessage` to other windows outside MOD-Host (`eslint.config.js:6-53, 88-110`). `pnpm lint`
  passes.
- **No content storage.** There is no `localStorage`, `sessionStorage`, `indexedDB`,
  `document.cookie` or `navigator.storage` anywhere in `src/` or `dist/`. Cache Storage is
  written only by `/sw.js`, and only through the allow-list in `src/host/offline-policy.ts:22-61`:
  same origin, `/` or `/index.html`, or a single `/assets/<name>` with no query. `blob:`,
  `data:`, `..` and other paths are refused. The page key is stored without its query
  (`:107`), seed lists are capped at 64 URLs (`:94`), and the worker checks
  `event.origin === ORIGIN` (`src/host/sw.ts:120`). The kill switch (`src/host/sw-kill.ts`)
  deletes only `json-formatter-*` caches. Nothing logs anything: there are no `console.*`
  calls in `src/`.
- **No analytics or telemetry in shipped dependencies.** The runtime is Preact, signals,
  CodeMirror, Lezer, lucide SVGs and Fontsource fonts (`package.json` dependencies, exact
  pins). The only "analytics" string in the bundle is the privacy copy text.
- **Headers** (`dist/_headers`, generated by `scripts/gen-headers.mjs:54-93`, and `pnpm
  gen:check` reports it up to date):
  - The CSP `script-src` hash `sha256-fYxLGKP0…ewO8=` matches the bytes of the inline boot
    script in `dist/index.html` (recomputed).
  - `connect-src 'none'`, `default-src 'none'`, `object-src`/`base-uri`/`form-action`/
    `frame-src`/`manifest-src 'none'`, `worker-src 'self'`.
  - `img-src data:` is needed: CodeMirror's `.cm-highlightTab` uses a `data:` SVG.
  - `frame-ancestors https://tarokit.app`. `HOST_ORIGINS` is validated: https only, no
    wildcard or path, and the build fails on a bad entry (`gen-headers.mjs:18-48`).
  - The other headers are present: HSTS 1 year with `includeSubDomains`, `nosniff`,
    `Referrer-Policy: no-referrer`, COOP `same-origin`, and a Permissions-Policy with only
    `clipboard-write=(self)`. There is no `X-Frame-Options` (correct for the frame-ancestors
    allow-list).
  - `/sw.js` detaches the page CSP with `! Content-Security-Policy`, then sets
    `default-src 'none'; connect-src 'self'` and `max-age=86400`. Other headers (HSTS,
    nosniff) still apply. There is no `report-uri`/`report-to`, so no reporting endpoint
    receives data.
- **postMessage.** Inbound messages are accepted only if `event.origin` is in the allow-list
  **and** `event.source === window.parent`, the data is a plain object and the value is
  `light`/`dark` (`src/host/contract.ts:27-39`). The listener exists only when the tool is
  embedded and the allow-list is non-empty (`src/host/index.ts:36`). Outbound, the tool sends
  only `{type:'taro:ready'}` with explicit target origins, never `*` (`contract.ts:58-68`,
  `index.ts:49-55`). The `?theme=` value is only compared against literals (`boot.js:7-12`,
  `theme.ts:11-17`).
- **XSS.** Every user-derived string reaches the DOM through `textContent`, an input `.value`,
  Preact text, or CodeMirror (`src/tree/view.ts:407,417,456,494`). The two HTML sinks write
  build-time lucide SVG constants keyed by a typed name (`src/tree/view.ts:96`,
  `src/app/components/Icon.tsx:43`). Issue messages are built from `{line}`/`{column}`/
  `{bracket}`-style numbers and fixed copy, never from document text. File names go only into
  `textContent`/`dataset`/`a.download`. The dedicated module worker accepts messages only from
  its creator.
- **Clipboard and download.**
  - Copying uses `navigator.clipboard.write`, called synchronously from the click handler
    (`src/io/index.ts:152-176`). The tool never reads the clipboard (`clipboard-read=()`);
    paste comes from the native paste event (`src/editor/index.ts:295`).
  - Downloads use a `blob:` URL plus `a.download`, and the URL is revoked after 60 s
    (`src/io/index.ts:202-212`). No request leaves the device.
  - The manual-copy field is read-only (`src/tree/view.ts:180-183`).
- **Editor input hygiene.** CodeMirror sets `spellcheck="false"`, `autocorrect="off"` and
  `translate="no"` on its content (`@codemirror/view` `dist/index.js:8308-8312`). The find
  field has `autocomplete="off"` and `spellcheck={false}` (`SearchPanel.tsx:65-66`).
- **Secrets.** There are no keys, tokens, `.env`, `.npmrc`, `.pem` or wrangler credentials in
  the tracked tree or the git history. The secret-like hits are test fixtures
  (`tests/unit/host-offline.test.ts:89-110`). The only `.env` on disk is inside a
  style-dictionary example under an ignored worktree's `node_modules`.
- **Source maps.** `sourcemap: 'hidden'`: no `sourceMappingURL` comment appears in any shipped
  JS (the only matches are inside the `sourcesContent` strings of `index--LrwBnkG.js.map`).
  The maps contain relative paths only (no `/Users/…`) and the project's own source, with no
  secrets. They are harmless if exposed. `public/.assetsignore` (copied to
  `dist/.assetsignore`) excludes `*.map` and `.vite` from upload. See MJ-1 for verification.
- **Supply chain.**
  - `pnpm install --frozen-lockfile` in CI. `pnpm-lock.yaml` has 676 `integrity:` entries and
    no tarball, git or codeload resolutions.
  - `minimumReleaseAge: 4320` (3 days). Dependency lifecycle scripts stay blocked (pnpm
    default).
  - All direct dependencies are exact-pinned.
  - The CI actions are pinned by SHA, and each SHA matches its upstream tag (checked with
    `gh api …/tags`): checkout v7.0.1 `3d3c42e…`, pnpm/action-setup v6.1.0 `ea17c68…`,
    setup-node v7.0.0 `8207627…`.
  - CI runs with `permissions: contents: read`. A license audit runs in CI.
- **Earlier review findings are resolved**: F-008 M1 (origin validation), M2/M3 (lint gaps), M4

## Major

### MJ-1 — Deploy-time controls are not in the repo, so headers, `.assetsignore` and framing are unverified in production
- **Location:**
  - `.github/workflows/` contains only `ci.yml`. There is no publish workflow, no
    `wrangler.json[c]`/`wrangler.toml`, and no post-deploy smoke test.
  - The configuration these depend on: `public/.assetsignore:1-3` and `public/_headers`.
  - The requirement: ADR-0009 "post-deploy smoke test" and ADR-0012 "Open: confirmation of
    Cloudflare's `_headers` merge".
- **Impact:** every network-level guarantee rests on Cloudflare applying `dist/_headers`
  exactly as generated.
  - If the publish step points at the wrong directory, or Cloudflare's `!` detach or merge
    differs from the emulation, then:
    - the page could ship without `connect-src 'none'` and `frame-ancestors`. Any site could
      then frame the tool, and click-jacking of Copy/Download becomes possible (NFR-09,
      F-008.AC8 broken), and NFR-01's "policy header present" fails;
    - or `/sw.js` could carry both CSPs, and offline support breaks (ADR-0009 measured this).
  - If `.assetsignore` is not honoured, about 2.4 MB of source maps and `.vite/manifest.json`
    become public. That is harmless in content but contradicts ADR-0003.
  - A "Single Page Application" not-found mode would also return `200 index.html` for unknown
    `/assets/*` paths (see I-5).
- **Fix:** before release, add:
  1. A SHA-pinned `publish.yml`:
     - triggered on `workflow_run` of CI success on `main`;
     - `permissions: contents: read`;
     - a GitHub Environment with required reviewers;
     - `CLOUDFLARE_API_TOKEN` scoped to "Workers Scripts: Edit" for this one project only;
     - `HOST_ORIGINS` set explicitly.
  2. `wrangler.jsonc` with `assets.directory: "./dist"` and the default (404) not-found
     handling.
  3. A smoke job against the live URL that:
     - asserts the exact CSP/HSTS/nosniff/Referrer/Permissions/COOP values on `/`, on one
       `/assets/*.js` file and on `/sw.js`, and that `/sw.js` has exactly one CSP;
     - asserts `404` for `/assets/<entry>.js.map`, `/sw.js.map` and `/.vite/manifest.json`;
     - runs the existing e2e framing test (unlisted origin refused) against production.

### MJ-2 — Browser page translation can send tree-view document text to a translation service
- **Location:**
  - `index.html:2` (`<html lang="en">`, no `translate="no"`).
  - Tree rows write keys and values as plain DOM text: `src/tree/view.ts:290` (row element),
    `:407` (key), `:417` (value), `:456` (`pathOut` path and its `title`, `:457`).
- **Scenario:** a developer whose browser is set to "always translate English" (common outside
  English locales, including this team's) opens the tree view on a JSON file holding API keys
  or personal data. Chrome's built-in translation sends visible text nodes to Google's
  translation service; Edge sends them to Microsoft's. The editor is protected because
  CodeMirror marks its content `translate="no"`, but the tree view, the selected-path header
  and its tooltip are not. This breaks the promise of COPY-privacy.details ("never uploaded")
  and INV-02 in practice, even though the tool itself makes no request.
- **Fix:** add `translate="no"` to `root` (`src/tree/view.ts:135`), or at least to the
  viewport (`:194`) and `pathOut` (`:140`), and to any future element that shows document
  text. Optionally add `<meta name="google" content="notranslate">` to `index.html`; the UI
  copy is English-only anyway. Add an e2e assertion that every node containing document text
  has a `translate="no"` ancestor. Also set `spellcheck=false` and `autocomplete="off"` on the
  manual-copy input (`:180`) for consistency.

## Minor

### mn-1 — Trusted Types not enforced; two `innerHTML` sinks remain
- **Location:**
  - `src/tree/view.ts:96`
  - `src/app/components/Icon.tsx:43`
  - The CSP in `scripts/gen-headers.mjs:54-70` has no `require-trusted-types-for 'script'`.
- **Impact:** defence in depth only. Today both sinks receive build-time SVG constants. A
  future change that routes user text into either sink would be an XSS in a page that handles
  secrets, and nothing at runtime would stop it. (`connect-src 'none'` limits exfiltration,
  but navigation or `a.href` exfiltration is not covered by CSP.)
- **Fix:** build icons as DOM nodes, for example by parsing the SVG once at module load with
  `DOMParser` (`image/svg+xml`) and cloning. Then add
  `require-trusted-types-for 'script'; trusted-types tk-worker` with one policy for the worker
  URL (ADR-0009 already plans this). Verify zero violations in the e2e matrix.

### mn-2 — CI checkout persists the `GITHUB_TOKEN` in `.git/config`
- **Location:** `.github/workflows/ci.yml:24`.
- **Impact:** every later step (`pnpm install`, tests, Playwright, LHCI dev dependencies) can
  read the token from `.git/config`. It is read-only (`contents: read`), which limits the
  damage of a compromised dev dependency, but there is no reason to expose it.
- **Fix:** add `with: { persist-credentials: false }` to `actions/checkout`. Use the same
  setting in the future publish workflow.

### mn-3 — The JSONTestSuite download is not integrity-checked
- **Location:** `scripts/fetch-jsontestsuite.mjs:27-31,48`. The script computes and prints the
  tarball's sha256 but never compares it.
- **Impact:** CI downloads and extracts a tarball over the network on every run. The commit
  pin trusts GitHub's codeload. A tampered or substituted archive would silently change the
  conformance corpus. This is test-only and limited to `tar -xzf` of two named paths.
- **Fix:** pin `JSONTESTSUITE_SHA256` next to the commit and fail on mismatch before
  extracting.

### mn-4 — pnpm supply-chain settings could be stricter
- **Location:** `pnpm-workspace.yaml:1-4`.
- **Impact:** the release-age gate and the frozen lockfile are in place. However, nothing
  fails the install when a dependency's publish provenance or trust level drops (a typical
  account-takeover signature), when a transitive dependency resolves to a git or tarball
  source, or when a new dependency silently has a blocked build script.
- **Fix:** add `trustPolicy: no-downgrade`, `blockExoticSubdeps: true` and
  `strictDepBuilds: true` (verify against pnpm 11.25 defaults; omit any that are already
  default). Keep `minimumReleaseAgeExclude` empty.

### mn-5 — The dev tool `@lhci/cli` → `lighthouse@12.6.1` bundles Sentry error reporting
- **Location:**
  - `package.json` (`"lhci": "lhci autorun"`).
  - `node_modules/.pnpm/lighthouse@12.6.1…/lighthouse/cli/bin.js:110-116` and
    `cli/sentry-prompt.js:24`. `@sentry/node@7.120.4` and `configstore@5.0.1` are reached only
    via `lighthouse`.
- **Impact:** nothing is shipped. Lighthouse asks for opt-in error reporting in an
  interactive terminal, and it is off when not in a TTY or when `CI` is set. A developer who
  answers "yes" locally sends crash reports, including run URLs and settings, to Google's
  Sentry. This is not user content, but it is telemetry in the toolchain, which the audit
  scope asked about.
- **Fix:** make the script `"lhci": "CI=1 lhci autorun"`, or pass
  `--no-enable-error-reporting` through `ci.collect.settings`. Note this in
  `specs/40-technical/dependencies.md` DEP-28.

### mn-6 — The Permissions-Policy does not deny every powerful feature the tool never uses
- **Location:** `scripts/gen-headers.mjs:79`.
- **Impact:** low, because no third-party code runs. Explicit denial still removes surface if
  a host `allow=` attribute or a future dependency asks for these features.
- **Fix:** append
  `fullscreen=(), display-capture=(), browsing-topics=(), local-fonts=(), hid=(), serial=(), bluetooth=(), idle-detection=(), screen-wake-lock=(), publickey-credentials-get=(), otp-credentials=(), storage-access=()`.
  Keep `clipboard-write=(self)` and `clipboard-read=()`. Update `tests/unit/headers.test.ts`.

## Info (no action required)

- **I-1** `src/app/Formatter.tsx:38` mirrors the loaded file name (and byte and line counts)
  into `data-source-name` on the root, as an e2e hook (`tests/e2e/f001-load.spec.ts:40`).
  This adds no exposure beyond the DOM and stays in memory, but it is document-derived
  metadata in markup. Consider gating it behind a test build flag.
- **I-2** No `Cross-Origin-Resource-Policy` header. Other origins can load the public static
  `/assets/*` files as `no-cors` resources. They contain no secrets, so adding
  `Cross-Origin-Resource-Policy: same-origin` is optional hardening (it does not affect the
  portal frame).
- **I-3** HSTS has no `preload`. `includeSubDomains` on a leaf subdomain has little effect;
  the apex `tarokit.app` (portal) should carry HSTS with `includeSubDomains` for real
  coverage.
- **I-4** After a `HOST_ORIGINS` change, an offline visitor still gets the cached HTML with the
  old `frame-ancestors` (`src/host/sw.ts:66-69`) until the next online opening. Removing a host
  origin therefore takes effect offline only after one online visit. Use the kill switch if an
  origin must be revoked immediately.
- **I-5** On an asset cache miss, the worker stores any `ok`, `basic`, non-redirected response
  (`src/host/sw.ts:79-80`). If the host ever answers unknown `/assets/*` paths with
  `200 index.html` (SPA mode), HTML would be cached under an asset key. This is an integrity
  issue, not a privacy one, and is covered by MJ-1's "default 404" requirement. Optionally,
  also require a JS/CSS/font `content-type`.
- **I-6** `.idea/.gitignore` is tracked; `.idea/workspace.xml` is not. Nothing sensitive.

## Data collected (for store/portal declarations)

**None.** The tool collects, transmits, stores and logs no user data:
- There are no accounts, cookies, identifiers, analytics, crash reporting or third-party
  requests.
- Document content and file names stay in page memory and the tool's own worker, and are
  discarded when the page closes. The browser may page memory to its own temporary files
  (D-028).
- Cache Storage holds only the tool's own static files (HTML, JS, CSS, fonts) for offline use.
- The only message to the portal is `{type:"taro:ready"}`.
- The only post-load requests are the browser fetching or update-checking the tool's own
  files for the offline cache (D-021). They never carry content.
