JSON Formatter Styles
JSON Formatter · phase 2 · style directions

Three ways to dress the formatter in Night Market

All three use the taro-kit portal's own tokens (colors, Manrope, JetBrains Mono, 4 px grid), so the tool sits naturally inside the portal frame. They differ in density, chrome and how loud the controls are. Each mock is the real Formatter screen from the spec; switch between its valid, error and tree states, and flip the theme.

Direction A

Workbench

An editor first. Thin toolbar, gutter and status strip like an IDE, a "Problems" dock for issues, small radii and hairlines everywhere. Most lines of JSON on screen. Beautify is the only filled button.

Density 38 px toolbar · 20 px lines
Type 13 px mono · 13 px UI
Shape radius sm (7 px), hairlines
Issues docked panel with tabs
Direction B

Market

Closest to the portal's own pages. Toolbar and editor are separate rounded cards, pill status chips, a soft accent glow on Beautify. Friendlier, a little less dense.

Density 50 px toolbar · 22 px lines
Type 13.5 px mono · 14 px UI
Shape radius md/lg, pills
Issues card under the editor
Direction C

Terminal

Mono everywhere, no fills, no icons. Actions are lowercase words; the accent only marks the active view and the primary action. The quietest and densest, but less discoverable for mouse users.

Density 34 px toolbar · 19 px lines
Type 12.5 px mono for all
Shape square, dashed dividers
Issues plain list, no chrome

My recommendation: A · Workbench, matching your "pro / dense, VS Code-like" answers, while borrowing B's pill status chip for the validity state so it reads clearly at a glance.
