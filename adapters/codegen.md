# Code generation adapter

How build scripts turn specs into code (MOD-Build, ADR-0003, ADR-0009, ADR-0011). Generated
files are checked in, never edited by hand, and regenerated by `pnpm gen` (also the first step
of `pnpm dev` and `pnpm build`). CI runs `pnpm gen:check`, which fails when any checked-in output
differs from what the generators produce.

| Generator | Source (spec) | Output (checked in) | Consumed by |
|---|---|---|---|
| `scripts/gen-tokens.mjs` | `specs/30-experience/tokens.json` | `src/app/styles/tokens.gen.css`, `src/app/styles/tokens.gen.ts` | all CSS (`var(--tk-…)`), editor theme |
| `scripts/gen-copy.mjs` | `specs/30-experience/copy.md` | `src/copy/messages.gen.ts` | MOD-Copy `t(id, params)` |
| `scripts/gen-notices.mjs` | `specs/40-technical/dependencies.md` + installed packages | `public/third-party-notices.txt` | shipped at `/third-party-notices.txt` |
| `scripts/gen-headers.mjs` | `src/host/boot.js` + `HOST_ORIGINS` | `public/_headers` | Cloudflare static assets, e2e server |

`scripts/gen-all.mjs` runs all four; `--check` compares instead of writing.

## Tokens → CSS custom properties
- Style Dictionary 5 (DEP-20) formats the values; the script only splits the colour themes.
- Names: `--tk-<path in kebab case>`, e.g. `color.lineStrong` → `--tk-color-line-strong`,
  `space.4` → `--tk-space-4`, `font.size.code` → `--tk-font-size-code`,
  `size.icon.sm` → `--tk-size-icon-sm`. Colour names drop the theme segment (`color.dark.bg` and
  `color.light.bg` are both `--tk-color-bg`).
- Scheme (same as the portal): everything inside `@layer tokens`; **dark** values and all
  non-colour tokens on `:root`; **light** colours under `[data-theme="light"]`; a
  `prefers-color-scheme: light` block for `:root:not([data-theme])` (only reached when the boot
  script did not run); `color-scheme` set per theme.
- `contrast` is metadata for `tools/token_contrast.py`, not emitted.
- `tokens.gen.ts` exports `TOKEN_VARS` (token path → custom property), `TokenName`, `Theme`,
  `THEMES`, `DEFAULT_THEME` and `tokenVar(name)` for script-side needs (editor theme).

## copy.md → message catalog
- Every table row whose first cell is `**COPY-<group>.<name>**` becomes
  `MESSAGES["<group>.<name>"]` with the second cell as text, taken literally (backslashes kept).
- Rows whose notes contain "deprecated" are skipped (today: `COPY-error.download`, D-023).
- `{placeholder}` names become a typed parameter object in `MessageParams`; `t()` in
  `src/copy/index.ts` requires exactly those parameters at compile time.
- Plural and size formatting rules from the notes column are implemented by MOD-Copy, not generated.

## Dependency registry → acknowledgements
- Reads every active (`candidate`/`approved`, not `removed` or spike-only) DEP row.
- For **runtime** and **asset** rows, each npm package named in the row that is installed is
  listed with its installed version, license and license file text. Registered packages not yet
  installed are reported on the console and appear once they are added.
- Rows with a CC-BY license (build-time data, e.g. `caniuse-lite`) get an attribution line.

## Boot script and `_headers`
- `src/host/boot.js` is the only inline script. `scripts/lib/boot.mjs` strips its comment-only
  lines and trims it; the Vite plugin in `vite.config.ts` inlines exactly those bytes at
  `<!--boot-->` in `index.html`, and `gen-headers.mjs` puts their SHA-256 in `script-src`.
  Changing the boot script without `pnpm gen` makes `gen:check` fail (and the e2e theme test).
- `HOST_ORIGINS` (space- or comma-separated; default `https://tarokit.app`; empty → `'none'`)
  sets `frame-ancestors` and the compiled-in `__HOST_ORIGINS__` allow-list of MOD-Host. The
  checked-in `public/_headers` uses the default; a deploy for another host list runs `pnpm build`
  with `HOST_ORIGINS` set.
- Rules: `/*` page policy (CSP of ADR-0009, Permissions-Policy, Referrer-Policy, nosniff, COOP,
  `Cache-Control: no-cache`); `/assets/*` detaches `Cache-Control` and sets 1-year immutable;
  `/sw.js` detaches the page CSP and `Cache-Control` (`! Name`, because Cloudflare joins
  duplicate headers) and sets `default-src 'none'; connect-src 'self'` and `max-age=86400`.
- `public/.assetsignore` keeps source maps and the Vite manifest out of the deployment.

## Other build scripts
- `scripts/check-size.mjs` (`pnpm check:size`): gzip size of `dist/index.html` plus every script,
  module preload and stylesheet it references; fails above 250 KB total or 250 KB JS (NFR-05).
- `scripts/check-licenses.mjs` (`pnpm check:licenses`): `pnpm licenses list` against the ADR-0001
  allow-lists — shipped packages must use allowed licenses and be registered as runtime/asset;
  direct dev dependencies must be registered; build/test-only exceptions (MPL-2.0 `lightningcss`,
  `axe-core`, `@axe-core/playwright`; CC-BY-4.0 `caniuse-lite`) are matched by name. Packages
  without an SPDX license are listed in `REVIEWED` after reading their license file. Production
  transitives that tree-shaking removes are registered with kind `unbundled`. It then runs
  `scripts/check-dist.mjs` on `dist/` (so `pnpm build` first): packages from the source maps,
  `@license` banners and the Vite manifest must be runtime/asset rows, fonts/images must trace to
  a registered package, unknown file types fail, and the shipped notices must list exactly the
  shipped packages and versions.
- `scripts/fetch-jsontestsuite.mjs` (`pnpm fixtures:jsontestsuite`): see `adapters/tests.md`.
